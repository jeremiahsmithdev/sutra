## Accepted Findings

### 1. HV: cumulative cost cap is not enforced across a queue run — `ralph-g2o5.1`

**Category:** Outer-loop orchestration gap (2)

**Evidence:** `lib/args.sh:316-317` resets `total_tasks_completed=0` and
`total_loops=0` on startup, and each queue entry re-execs a fresh ralph
process (`lib/queue.sh:122 maybe_reload_ralph`). `lib/circuit_breaker.sh:41`
enforces `MAX_COST_USD` against the per-entry `total_cost_usd` in `.ralph/state`
— which begins at 0 for every queue entry. After this run, `.ralph/state`
showed `total_cost_usd=3.42` while the run actually spent ~$140.
`lib/queue_log.sh` already accumulates a queue-wide `_queue_log_total_cost`,
but the circuit breaker never reads it. Net effect: `--max-cost` silently
degrades to a per-playlist cap on a queue run, with no signal to the operator.

### 2. HV: #REFACTOR gate ignores cleanup items pre-flagged in epic notes — `ralph-g2o5.2`

**Category:** Gate template (4)

**Evidence:** In `marketing-data-connectors`, the epic notes for `chippie-kji3`
explicitly named `_TARGET_COUNTRIES` dead code as a "#REFACTOR" item. The
`#REFACTOR` line was processed but the code was not removed — the code harvest
had to raise a separate chore. `templates/gate_refactor.txt` Phase 1 derives
scope purely from `git diff`; it never reads the parent epic's `notes` field,
so operator-identified cleanup is invisible to the gate.

### 3. HV: trailing bead after the final gate cluster — silently skipped — `ralph-g2o5.3`, `ralph-g2o5.4`

**Category:** Outer-loop orchestration gap (2) + bead-description shape (3)

**Evidence:** Three validated playlists each end with a bare bead ID authored
*after* the final gate cluster (`#REFACTOR` / `#DOCUMENT`): `chippie-lpb1j`
(ios-safari, line 22), `chippie-wpunj` (seo-phase-2), `chippie-i1os3`
(ai-substrate). Each completion report flags it as "not processed / unclear if
intentional." Code-confirmed mechanism: `lib/playlist.sh:162-167` —
`playlist_execute` skips already-closed beads via
`bead_already_closed → playlist_advance; return 0` with **zero log output**:
no LOOP banner, no log line. A skipped trailing bead is therefore invisible in
the session log, which is why the reports could not tell whether it ran.

Split into two beads:

- **`ralph-g2o5.3` (a) Observability** — `playlist_execute` emits a one-line
  `skipped (already closed)` log when it takes the `bead_already_closed`
  branch (`lib/playlist.sh`).
- **`ralph-g2o5.4` (b) Authoring** — `ralph playlist init` Phase 1
  (`lib/playlist_validate.sh`) warns when a bare bead ID appears after the
  trailing gate cluster.

## Rejected Candidates

### 1. Extract the PRIME prompt into a `#PRIME` gate

**Rejected:** Not a methodology finding. The ~600-word PRIME planning-grounding
prompt is byte-identical across all 8 playlists, which *looks* like a
re-injected-spec anti-pattern — but `grep -rln PRIME templates/ skills/`
returns nothing: the prose is hand-authored by the operator and pasted into
each playlist, not generated by ralph or the playlist-create skill. The
duplication is an authoring choice, not a ralph defect. Making `#PRIME` a real
gate tag would be a legitimate *feature request* (ralph owns the prose, author
writes one word) — but that is a product decision for the operator, outside
the scope of a methodology harvest.

### 2. Tighten the inline-CSS smoke-test grep to catch `style="` attributes

**Rejected:** Guardrail 6 — no clean template home. In `blog-engine-aeo` a
smoke-test missed an inline `style="font-size:1rem"` because its grep matched
only `<style>` tags. That grep lived in the playlist's hand-authored
smoke-test context line, not in `templates/gate_smoke_test.txt` (which has no
such grep). There is no single template owner to change.

### 3. Make playlists for service-layer work mandate committed test beads

**Rejected:** Guardrail 1 — loop placement. `marketing-data-connectors` and
`chip-ai-tier-a` shipped non-trivial logic with zero test files. Whether a
change warrants committed tests is inner-loop / author judgment, not a
hardcoded outer-loop rule. `#SMOKE_TEST` gates are intentionally manual
verification.
