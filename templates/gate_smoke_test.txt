## Preconditions (run before any checks)

Run these steps in order. If a step fails, STOP immediately — do not proceed
to the Checks section.

1. **Start dev server.**
   Consult the project's README or CLAUDE.md for the standard run command
   (e.g. `flask run`, `npm run dev`, `rails server`).

   **Pick a free port before starting.** Other instances of this app may
   already be running — most commonly when this checkout is a git worktree
   and the main checkout is also serving on the default port. Procedure:
   * Run `git worktree list` — if more than one entry exists, treat the
     default port as potentially taken.
   * If `SUTRA_DEV_PORT` is set in the environment, use it.
   * Otherwise probe with `lsof -i :<default-port>` (or `nc -z localhost <port>`)
     and pick the first free port at or above the default. Pass it via
     the framework's standard env var or flag (`PORT=<n>`, `--port <n>`,
     `-p <n>`, etc.) so curl checks below hit YOUR server, not another
     worktree's.
   * Record the chosen port: `DEV_SERVER_PORT=<n>`.

   Start in the background and capture its PID:
   ```
   <run-command-with-port> &
   DEV_SERVER_PID=$!
   ```
   Wait up to 15 s for it to respond (poll the health endpoint or root URL
   on `$DEV_SERVER_PORT`).

2. **Confirm the server is reachable.**
   `curl -sf <health-endpoint-or-root>` must return 2xx. If it does not
   within 15 s, the server failed to start — go straight to Precondition
   Failure handling below.

3. **Establish auth / tenant context (if the project requires it).**
   * Check for seed fixtures in `tests/helpers/`, `tests/conftest.py`,
     `tests/fixtures/`, or similar. Use them to obtain a session token,
     API key, or cookie — do NOT fabricate credentials.
   * If the project is multi-tenant, pick one tenant from the seed data.
   * If no auth fixtures exist, note "no auth required" and continue.

**Precondition Failure:** If ANY step above fails, create ONE bug bead:
```
br create --type=bug --title "SMOKE: preconditions failed — <which step>"
```
Append the bead ID to the playlist file as a **bare ID on its own line** —
sutra's parser only recognises that form. Then stop. Do NOT attempt any checks.

```
# Correct — sutra will pick this up on the next loop:
chippie-ow6k

# Wrong — sutra treats the whole bullet as the task identifier and the
# claim returns status 'unknown':
* [bead] chippie-ow6k — SMOKE precondition failure: missing module
```

Use plain `echo "<bead-id>" >> "$PLAYLIST_FILE"` (no markdown, no prefix,
no trailing notes on the same line). If you need to record context, put it
in the bead's description via `br create --description`, not in the playlist.
