## Preconditions (run before any checks)

Run these steps in order. If a step fails, STOP immediately — do not proceed
to the Checks section.

1. **Start dev server.**
   Consult the project's README or CLAUDE.md for the standard run command
   (e.g. `flask run`, `npm run dev`, `rails server`). Start it in the
   background and capture its PID:
   ```
   <run-command> &
   DEV_SERVER_PID=$!
   ```
   Wait up to 15 s for it to respond (poll the health endpoint or root URL).

2. **Confirm the server is reachable.**
   `curl -sf <health-endpoint-or-root>` must return 2xx. If it does not
   within 15 s, the server failed to start — go straight to Precondition
   Failure handling below.

3. **Establish auth / tenant context (if the project requires it).**
   * Check for seed fixtures in `tests/helpers/`, `tests/conftest.py`,
     `tests/fixtures/`, or similar. Use them to obtain a session token,
     API key, or cookie — do NOT fabricate credentials.
   * If the project is multi-tenant, pick one tenant from the seed data.
   * If no auth fixtures exist, note "no auth required" and continue.

**Precondition Failure:** If ANY step above fails, create ONE bug bead:
```

```
Append the bead ID to the playlist file after this line, then stop.
Do NOT attempt any checks.
